# 自然对话

AstrBot 插件，尽量去除常见AI腔，让模型在日常对话与日常工作里给出的回复更像真人说话。在模型调用前注入对话约束，并跟踪近期高频重复的开头与命中套话，在后续轮次提示模型换个说法。

写代码、写脚本、写通知、写周报这类日常工作照常生效。用户要求改语气、或贴来一段要转手的成品文本时，这一轮让位。

主要功能：

1. **固定规则**：写入 system prompt 的基础约束，保持现有角色设定，取自 natural-talk。可用 `/natural rules` 查看。
2. **动态提醒**：记录近期回复开头与命中的套话，在下一轮作为简短提示传入，要求更换表达。

## 快速开始

在 AstrBot 管理面板 → 插件市场导入本仓库，或解压 release 包到插件目录。默认全部开启。修改配置后需在管理面板**重载插件**。依赖 AstrBot `>=4.23,<5`。

## 命令

指令组 `natural`，所有子命令限**管理员**使用；除 `/natural rules` 外都作用于**当前会话**。

| 命令 | 作用 |
|------|------|
| `/natural status` | 查看当前启用状态、动态提醒状态与累计注入次数 |
| `/natural on` | 启用当前会话 |
| `/natural off` | 禁用当前会话 |
| `/natural reset` | 清空当前会话的提醒记录 |
| `/natural rules` | 查看当前固定规则原文 |
| `/natural stats` | 查看本次进程运行的统计数据 |

## 配置

| 配置项 | 默认 | 说明 |
|--------|------|------|
| `enabled` | true | 总开关。关闭后插件仍加载，但不注入规则、不记录状态 |
| `inject_stable_rules` | true | 注入固定规则。与其它改写 system 的插件冲突时可关闭 |
| `inject_runtime_state` | true | 注入动态提醒；关闭后仍记录轻量状态 |
| `max_runtime_hint_chars` | 157 | 每轮动态提示的最大字符数（80–157），只装入完整短语。含顿号或换行的避用词无法装入提示，只在 `/natural status` 里列出 |
| `recent_reply_window` | 8 | 重复开头看最近 N 条（3–50） |
| `state_retention_days` | 14 | 会话状态超过该天数未更新则清理（1–365） |
| `custom_cliches` | 空 | 自定义避用词，每行一个 |
| `disabled_sessions` | 空 | 禁用会话列表，每行一个群号（如 `123456`）或完整来源标识 |
| `debug_log` | false | 调试日志，每轮记录本次注入与清理情况（不含聊天正文与避用词原文） |

## 检测项目

检测器只收无需读语境就能判定的高置信形态，放行正常的技术与业务表述。代码块（含 `~~~`）、行内代码与 URL 不参与检测，引号里的他人原话与台词也不参与句式判定。命中项按危害分档：可靠性损害（身份暴露、假归因、谄媚整句、翻案腔）优先于观感项进入下一轮提示。

- **末尾模板**（仅结尾匹配）：客服收尾（`希望能帮到你`、`随时联系我`、`I hope this helps`、`如有疑问`）、空泛打气（`未来可期`、`一起加油`）、万能收尾（`关键在于平衡`、`要结合实际情况`、`因人而异`、`视情况而定`、`没有标准答案`、`看具体情况`）、总结套话（`综上所述`、`由此可见`）
- **AI 身份暴露**（全句匹配）：`作为AI`、`作为一个语言模型`、`根据我的训练`、`截至我的知识更新` 等
- **开场套话**（仅首部匹配，真实动作开场豁免）：`好问题`、`问得好`、`让我来`、`关于你提到的`、`你问到了核心`、`在当今快速发展的时代`、`众所周知`、`说白了`、`简单来说`、`先说结论`、`说到底`、`归根结底`、`直接给答案` 等
- **谄媚整句**（全句匹配）：`我完全理解你的感受`、`你说得太对了`
- **模糊归因**（全句匹配）：`有研究表明`、`业内普遍认为`、`业内认为`、`专家指出`、`不少用户反馈`
- **特定句式**：
  - `翻案腔`（`不是…而是`、`其实不是…只是`、`与其…不如`、`看似…实则`、`不在于…而在于`、`真正的问题是`）。`不是只/仅 + 两字内限制词…而是` 的限量否定与用户已给前提下的纠错句放行；`看似`、`与其`、`不在于` 三种句式不放行。用户点名要定位某处问题时，先排除再定位的答案也算有效信息
  - `结尾拔高`（`不仅是…更是/更关乎`）
  - `空转提示语`（`总结如下：`、`建议如下：`、`核心是：`）
  - `揭示式破折号`（`——那就是`、`——原来`，以及破折号夹解释、解释完用分号落回原句的形态）。并列停顿、话被打断不报
- **密度项**（按篇幅折算，基准 300 字）：感叹号 >3 次、路标词堆砌 >2 次、`然而` 连发 ≥2 次
- **推测词叠加**：同一句出现 ≥2 个不确定标记（`可能`、`也许`、`大概` 等）。单个 `可能` 是诚实，保留；`可能是，也可能只是` 这种并列分叉也放行
- **重复开头**：统计最近 8 条回复，同一开头出现 ≥3 次触发提醒，涵盖 `确实`、`当然`、`对的`、`没错`、`哈哈` 等常见口头语
- **自定义避用词**（`custom_cliches`）：命中配置词即加入下一轮提示；单个词超过 20 字忽略

## 让位规则

以下两类请求，本轮不注入固定规则、不追加动态提醒：

- **改语气**：两种说法都算。一是「改动动作 + 指代对象或文书体裁」，如 `把这段话润色一下`、`帮我改写这封邮件`、`顺一下这篇文档`；二是本身即成立的语气要求，不用带指代对象，如 `改成正式语气`、`这段文字太AI了`、`写得自然点`、`说自然一些`、`口语化一点`。后续 `继续改`/`同上` 这类续写口令在 5 分钟内继续让位，普通短消息不算。
- **转手成品文本**：含 `原文如下：`（前面可带 `[图片]`、`@某人` 等前缀）且正文达到 60 字，且没有夹带润色/翻译类任务。

## 工作原理

- **固定规则**：写入 `system_prompt`，用 marker 标识防重，不写入聊天历史。
- **动态提醒**：随单轮请求发送，并在每轮请求前清理历史上下文里的旧注入块。
- **容错处理**：宿主临时文本部件不可用时动态提醒自动降级，固定规则保持生效；写盘失败时先留在内存，下次操作或关闭时重试落盘。插件内部异常不阻断消息主链。

## 数据存储

状态文件位于插件数据目录的 `runtime_state.json`，不保存聊天全文。只记录三样：禁用会话、最近回复的开头（最多 8 字）、以及下一轮要避用的条目。命中 `custom_cliches` 的自定义词按序号写盘，原文不落盘，改配置后旧序号自动失效。状态文件损坏时备份为 `runtime_state.corrupt.<时间戳>.json` 后重建，最多保留 5 份备份。
